## Chronos v0.1.1 — Windows startup repair

**Fixes the startup error** "Chronos local server stopped before it became ready" that appeared when opening the installed or portable v0.1.0 build.

### Cause
The Windows packages did not contain the local server's `node_modules` folder (electron-builder drops a root-level `node_modules` from extra resources). The bundled Next.js server therefore crashed immediately with `Cannot find module 'next'`, and the desktop host hid the error.

### What changed
- Server dependencies are now packaged, and the app validates its bundle before starting.
- Startup is logged to `%APPDATA%\Chronos\logs\chronos-startup.log` (agent output in `chronos-agent.log`).
- Startup errors name the real cause (missing files, database, port, timeout, process exit) and offer **Open log folder**.
- `/api/health` now checks the server, database, schema and data folder.
- The monitoring agent is verified by a real heartbeat before Chronos reports monitoring as active; if it fails, Chronos says so.
- The local server and database are stopped gracefully so the database is always flushed; no orphaned processes remain after exit.
- A second launch no longer starts a second server.
- Existing data under `%APPDATA%\Chronos` is kept on upgrade.

### Downloads
- `Chronos-Setup-0.1.1.exe` — installer
- `Chronos-Portable-0.1.1-x64.exe` — portable
- `SHA256SUMS.txt` — checksums

The executables are not code-signed; Windows SmartScreen may show a warning on first launch.
